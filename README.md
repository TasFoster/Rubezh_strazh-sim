# Симулятор СКУД Rubezh STRAZH

Учебный симулятор монтажа и пусконаладки системы контроля и управления доступом
**Rubezh STRAZH**: соединение клемм, адресация модулей, настройка через
веб-интерфейс контроллера, поиск и устранение неисправностей.

Работает в браузере, в 2D. Сервер не нужен.

> Статус: этап 0 — каркас проекта. Есть описание модуля STR-1AP по паспорту и
> демонстрационная страница с расчётом адреса OSDP.

## Запуск

Нужен Node.js 24 или новее.

```bash
npm install
npm run dev      # страница разработки на http://localhost:5173
npm run check    # линтер + проверка типов + тесты + сборка
```

| Команда | Что делает |
|---------|------------|
| `npm run dev` | локальный сервер разработки |
| `npm run build` | сборка в `apps/web/dist` |
| `npm test` | модульные тесты (Vitest) |
| `npm run typecheck` | проверка типов |
| `npm run lint` / `npm run format` | проверка и автоисправление (Biome) |

## Структура

```
packages/core/      ядро симуляции: модель устройств, клемм, шин. Без UI и браузера
packages/content/   каталог устройств и сценарии в виде данных (JSON)
apps/web/           интерфейс (React + Vite)
```

Правило зависимостей: `web → content → core`. Ядро не импортирует ничего из
интерфейса и не использует браузерные API — это проверяется сборкой
(`tsconfig.packages.json` не подключает типы DOM).

## Откуда берутся данные об устройствах

Каждое описание в `packages/content/devices/` содержит поле `source` — документ
производителя и его редакцию. Сами документы в этот репозиторий не входят: они
лежат в хабе [Rubezh_services](https://github.com/TasFoster/Rubezh_services)
(`datasets/rubezh-docs/strazh/docs`, восстанавливаются по манифесту).

Если в документе чего-то нет и значение выведено косвенно, это записано в поле
`note` соответствующей клеммы.

## План разработки

| Этап | Содержание | Результат |
|------|------------|-----------|
| 0 | Каркас, инструменты, CI, сбор паспортов | **сделано** |
| 1 | Ядро: устройство → клеммы → кабель → цепь; питание, полярность, падение напряжения, входы с контролем линии, реле | минимальный комплект (STR20-IP, STR-1AP, считыватель, замок, кнопка, геркон, БП) считается в тестах |
| 2 | Стенд монтажа: палитра устройств, соединение клемм, выбор кабеля, DIP-адрес, перемычки, индикация, мультиметр | комплект собирается мышью |
| 3 | Эмулятор веб-интерфейса контроллера: обнаружение, сеть, время, OSDP, поиск устройств, точки доступа, персонал, карты, журнал | проход по карте даёт событие в журнале |
| 4 | Сценарии и оценка: формат сценария, проверка шагов, подсказки, отчёт | три учебных сценария: дверь, двусторонняя дверь, турникет |
| 5 | Неисправности по таблице диагностики из руководства | режим «найди и устрани» |
| 6 | Расширение каталога: контроллеры с БП и АКБ, STR-2AP-M/3AP-M, OSDP-считыватели, турникеты, кластер | — |
| 7 | Выпуск: офлайн-режим, проверка на 1366×768, справка, пилот | публикация |

Интеграция с R-PLATFORMA в первую версию не входит.

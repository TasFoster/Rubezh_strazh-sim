# Симулятор СКУД Rubezh STRAZH

Браузерный учебный стенд для размещения оборудования на плане объекта,
соединения клемм и пусконаладки через отдельный веб-интерфейс каждого контроллера.
Первая рабочая версия; подробный статус — в [плане реализации](docs/IMPLEMENTATION.md).

## Запуск

Нужен Node.js 24 или новее.

```bash
npm ci
npm run dev
```

Откройте адрес, выведенный Vite (обычно `http://localhost:5173`).
Для знакомства выберите «Проект → Готовый пример» и нажмите «Запустить».
Приложите карту, откройте и закройте дверь, проверьте журнал. «Помощь → Задания»
открывает учебные сценарии; «Помощь → Справка» объясняет монтаж и управление.
Приборы и окна контроллеров доступны через меню «Симуляция».

## Возможности

- План: импорт PNG/JPEG, калибровка масштаба, стены, помещения-зоны, двери,
  этажи и отдельный фон каждого этажа.
- Рабочее поле: каталог, перетаскивание, поворот, копирование, сетка,
  масштабирование, перемещение камеры, отмена и повтор.
- Монтаж: соединение клемм, маршруты, многожильные кабели, длина/сечение,
  обрывы, DIP-адреса, перемычки, контроль линии входов и резисторы.
- Компоновка: автоматическое раздвигание карточек с учётом поворота,
  ортогональные провода в обход корпусов, разведение параллельных трасс,
  дуги на пересечениях без соединения. Ручные маршруты сохраняются;
  автоматическую прокладку можно выбрать в свойствах кабеля.
- Симуляция: питание, полярность, падение напряжения, перегрузка/КЗ, реле,
  замок, сухие контакты, мультиметр, обнаружение OSDP и конфликты адресов.
- Контроллеры: независимые окна, сеть/время, поиск и добавление устройств,
  точки доступа, карты/права, проходы и журнал.
- Примеры: одна дверь, двусторонняя дверь, учебный турникет, OSDP-считыватель,
  два независимых контроллера. Пять заданий с подсказками и JSON-отчётом.
- Автосохранение в браузере, проверяемый JSON-импорт/экспорт и работа без сети
  после первого открытия собранной версии.

Проект хранится в текущем браузере. Для резервной копии или переноса на другой
компьютер используйте «Экспорт». В экспорт включаются загруженные изображения.
Повреждённое автосохранение не перезаписывается автоматически.

Меню «Вид» содержит настройки сетки, свойства плана, этажи и компоновку.
Автомаршруты меняют рисунок проводов, сохраняя электрические соединения и заданную
длину кабеля. Произвольную схему не всегда можно развести на плоскости без
пересечений: оставшиеся пересечения показаны дугами. Если свободный выход от
клеммы перекрыт, редактор показывает конфликт. Ручные трассы автоматически не
перезаписываются; пересечение корпуса отмечается предупреждением.

## Сборка и проверки

| Команда | Результат |
|---|---|
| `npm run dev` | сервер разработки |
| `npm run build` | статическая сборка и service worker в `apps/web/dist` |
| `npm run preview` | локальная проверка сборки |
| `npm run check` | Biome, TypeScript, модульные тесты, сборка |
| `npm test` | модульные тесты Vitest |
| `npm run test:e2e` | браузерные проверки редактора и симуляции |
| `npm run test:e2e:production` | сборка и проверка работы без сети |
| `npm run format` | форматирование и исправления Biome |

Для браузерных тестов установите Chromium: `npx playwright install chromium`
(в Linux при необходимости `npx playwright install --with-deps chromium`).
Можно передать путь к установленному браузеру через
`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

Для размещения достаточно статического HTTPS-сервера с содержимым `apps/web/dist`.
Офлайн-режим требует HTTPS или localhost: дождитесь сообщения «Офлайн готов»,
после чего страницу можно перезагружать без сети. Открытие `index.html` через
`file://` не является поддерживаемым способом запуска. Сервер приложения и
подключение к настоящим приборам не требуются.

## Границы модели

Это учебный симулятор, не средство расчёта и приёмки реальной системы.
Электрическая модель ограничена DC-цепями с резистивными нагрузками, идеальными
источниками и контактами. Предельная размерность одной системы расчёта — 256;
неподдерживаемые цепи диагностируются. Ёмкости, индуктивность, АКБ, динамика
двигателей и побитовый обмен OSDP не моделируются.

STR20-IP представлен питанием и двумя линиями OSDP, STR-1AP — необходимыми для
учебного стенда клеммами. Остальная периферия явно обозначена как учебная.
Панель контроллера реализует основные операции пусконаладки; полная копия
прошивки, реальная сеть/DHCP и кластерная синхронизация пока отсутствуют.
Помещения являются прямоугольными зонами; автоматического распознавания
замкнутых стен нет. Полный каталог STR, АКБ и пользовательский пилот остаются
следующими этапами. Интеграция с R-PLATFORMA в эту версию не входит.

## Структура и источники

| Путь | Назначение |
|---|---|
| `packages/core` | модель проекта, расчёт цепей, время, события и оценка заданий |
| `packages/content` | каталог устройств, примеры, сценарии и проверки моделей |
| `apps/web` | React-интерфейс и SVG-редактор |
| `e2e` | браузерные проверки Playwright |
| `docs/SOURCES.md` | документы производителя и учебные допущения |

Зависимости направлены `web → content → core`. Ядро не использует DOM;
это проверяется отдельной конфигурацией TypeScript. Источники для реальных
моделей и редакции документов перечислены в [реестре](docs/SOURCES.md).

# План реализации STRAZH Simulator

Цель: браузерный учебный стенд по принципу Tinkercad Circuits. Пользователь
загружает или рисует план объекта, размещает оборудование, соединяет клеммы,
запускает симуляцию и настраивает отдельные контроллеры через их веб-интерфейсы.

## Проверка первой рабочей версии

Создать объект → загрузить план → расставить комплект одной двери → соединить
питание, OSDP, считыватель, реле, кнопку и геркон → задать адрес → запустить →
обнаружить модуль → создать точку доступа и карту → открыть по карте/кнопке →
увидеть события → сохранить и восстановить объект.

## Правила реализации

- Один проект является источником конфигурации для плана, монтажа и контроллеров.
- Каталог описывает модель; адрес, настройка и положение принадлежат экземпляру.
- Геометрия кабеля отделена от электрических соединений его жил.
- Временное состояние симуляции отделено от сохраняемой конфигурации.
- Ошибочный монтаж разрешён; его последствия рассчитываются и диагностируются.
- В первой версии используется ограниченная модель низковольтных DC-цепей.
  Неподдерживаемые режимы диагностируются, а не выдают выдуманные измерения.
- Макет интерфейса не считается точной копией прошивки без сверки с руководством.
- Реальные модели не получают придуманные характеристики. Для прототипа
  допустимы явно обозначенные учебные компоненты.
- Сервер для базовой работы не нужен; публикация выполняется отдельно.

## Проверки

Для ядра: топология цепей, некорректные проекты, адресация, независимость устройств,
питание, полярность, КЗ, таймеры, карты и события. Для браузера: действия редактора,
масштабирование, монтаж, сохранение, окна контроллеров и сквозная дверь.
Каждый кодовый шаг: `npm run check`; UI дополнительно проверяется в браузере.

## Журнал

- 01: согласованный план перенесён в репозиторий. Источники и неподтверждённые
  сведения перечислены в `SOURCES.md`. Исходная версия: `7bd512a`.

- 02: валидация диапазона DIP и ID колодок/перемычек/индикаторов, глубокая
  неизменяемость каталога, проверка адреса по диапазону устройства.

- 03–04: редактор на SVG без дополнительного графического фреймворка, история
  на 50 действий, импорт/экспорт и защищённое автосохранение. Проверено в Chromium
  на 1366×768: добавление, копирование, поворот, отмена и восстановление после
  перезагрузки. `npm run check`: 28 тестов проходят.

- 05: PNG/JPEG, фон с блокировкой, перемещением/поворотом/прозрачностью,
  калибровка двух точек. Chromium: загрузка изображения, масштаб 0,05 м/ед.,
  сохранение и восстановление фона проходят.

- 06: подробные клеммы, провод между выбранными клеммами, точки маршрута,
  независимые жилы, цвет/обрыв/длина/сечение, переподключение через свойства, DIP
  и перемычки. Chromium: соединение БП и замка, добавление второй жилы, обрыв
  и восстановление данных проходят. Добавлен ограниченный STR20-IP и учебная периферия.

- 07a: расчёт DC-цепей методом узловых потенциалов с источниками напряжения;
  сопротивление медных жил, резистивная нагрузка при номинале 12 В, реле и сухие
  контакты. Защита БП и выхода считывателей; неопределимые цепи явно диагностируются.
  35 тестов проходят. Мультиметр и взаимодействие с входами подключаются на шаге 08.

- 08: детерминированное время, защёлкивание DIP, физическая проверка OSDP,
  конфликты адресов, карты, реле, кнопка, геркон и удержание двери. Мультиметр
  и журнал подключены к модели. Chromium: карта → отпускание замка → открытие
  двери → событие; мультиметр БП 12,000 В; пауза. 38 модульных тестов проходят.

- 09: независимые окна STR20-IP: система, сеть/время, линии OSDP, поиск/добавление
  модулей, точки, карты и журнал. Это функциональный учебный объём, не полная
  копия всех 498 страниц РЭ. Chromium: ненастроенный стенд → поиск → добавление
  → точка → карта → проход успешно. IP и конфигурация сохраняются.

- 10: сквозные проверки оформлены в `e2e/simulator.spec.ts`: монтаж/восстановление,
  пусконаладка и проход, защита от повреждённого импорта. Запуск: `npm run test:e2e`.

- 11: стены с длиной, помещения-зоны с размерами и подписью, дверные проёмы
  с привязкой к стене и точке доступа, перетаскивание геометрии, отдельные этажи
  и фоны. Chromium: стена → дверь → помещение → второй этаж → устройство проходит.
  Помещение пока является прямоугольной зоной, не автоматическим распознаванием
  замкнутого контура стен; межэтажные трассы отображаются на исходном этаже.
